# trayiconguard (npm)

Keep every **notification-area (system tray) icon** visible on Windows 10/11 — and keep it that way.

This npm package is a thin wrapper around the official
[TrayIconGuard](https://github.com/paulmann/windows-show-all-tray-icons) Windows binary:

- it **does not bundle** the executable — the package stays a few kilobytes;
- it downloads the release asset and **verifies its SHA-256 against the project's update feed**
  before the binary is ever started;
- the verified copy is cached in `%LOCALAPPDATA%\TrayIconGuard\npm` and reused.

```console
$ npx trayiconguard install        # download + verify, then start the setup wizard
$ npx trayiconguard status --json  # machine-readable tray state
$ npx trayiconguard autostart on   # start with Windows (HKCU Run entry)
$ npx trayiconguard update         # check the feed and update in place
$ npx trayiconguard uninstall
```

| Command | What it does |
|---|---|
| `install` | download + verify, then start the GUI wizard (*Only for me* needs no admin; *For all users* asks for one UAC prompt) |
| `install --machine <dir>` | machine-wide install body — must run in an **elevated** shell |
| `download` | download + verify into the cache only |
| `run [--minimized]` | run the cached binary |
| `status [--json]` | print tray state (`--json` for automation) |
| `promote-all` | promote every hidden icon right now, then exit |
| `autostart on\|off` | add/remove the `HKCU\…\Run` autostart entry |
| `update` | check the git feed and apply a newer version non-interactively |
| `uninstall` | remove shortcuts, autostart and the installed copy |
| `exe` | print the path of the cached executable |
| `version` | wrapper version + the latest published binary version |

Options: `--version <v>`, `--url <direct-exe-url>`, `--feed <url>`, `--force`, `--no-verify`,
`--minimized`, `--machine <dir>`, `--json`, `-h`.

> **Known limitation (TrayIconGuard 8.6.0):** the binary prints CLI output through
> `WriteConsoleW` and rebinds `stdout`/`stderr` to the console, so its output is visible in an
> interactive terminal but is **lost when redirected** (`> file`, `| more`, RMM capture). This is
> an upstream defect fixed in the next release, not a wrapper bug — until then, read `--status`
> output on the console (or use the app's Activity log / `%LOCALAPPDATA%\TrayIconGuard\logs`).

## Requirements

- **Windows 10 1703+ or Windows 11, x64** (the binary is a native Win32 exe; the package declares
  `os: win32`, `cpu: x64`, so npm refuses to install it elsewhere).
- Node.js **18+** only to run this wrapper — TrayIconGuard itself has **zero runtime dependencies**
  (no .NET, no Visual C++ redistributable).

## What the binary does

It writes the same `HKCU\Control Panel\NotifyIconSettings\{id}\IsPromoted` values the Windows
Settings toggle uses (per user, no admin), and keeps a `RegNotifyChangeKeyValue` watcher on that
store so icons Explorer hides again are re-promoted within a fraction of a second. Extras: a
Fluent GUI with Light/Dark/System themes, 30 locales, JSON snapshots, an activity log, a headless
`--watch` mode, a full CLI with stable exit codes, and SHA-256-pinned self-updates. No telemetry.

## Security notes

- Every download is verified against the `sha256` field of
  [`update/stable.json`](https://raw.githubusercontent.com/paulmann/windows-show-all-tray-icons/main/update/stable.json);
  the daily feed is generated by the project's CI **from the bytes the GitHub release actually serves**.
- On a mismatch the file is deleted and the command aborts.
- Only the feed and the release asset are ever fetched — both over HTTPS.
- `--no-verify` exists for local debugging and is deliberately discouraged.

## Uninstall

```console
$ npx trayiconguard uninstall
$ npm uninstall -g trayiconguard     # if installed globally
$ rmdir /s "%LOCALAPPDATA%\TrayIconGuard\npm"
```

## Publication status — 2026-10-16

The package is finished and packed (`pnpm pack` → `trayiconguard-8.6.0.tgz`, 7 798 bytes, containing
`bin/trayiconguard.js`, `LICENSE`, `package.json`, `README.md`). End-to-end behaviour on Windows 11:

| Check | Result |
|---|---|
| `trayiconguard download` | downloads the release asset, SHA-256 matches `update/stable.json` ✅ |
| `trayiconguard status` / `status --json` | forwards to the real binary, exit code 0 ✅ (output is console-only — see the limitation above) |
| negative test (`--url` pointing at the zip while the feed pins the exe) | `SHA-256 mismatch`, exit 1, corrupted file deleted ✅ |
| `pnpm pack` | valid tarball, 7 798 B ✅ |

**Publishing is blocked by credentials.** `pnpm publish` (and `pnpm whoami`) fail with
`401 Unauthorized` / `404 Not Found`, i.e. the granular token in `%USERPROFILE%\.npmrc` is no
longer valid (expired or revoked). The registry name `trayiconguard` was free at the time of
writing.

To publish, refresh the credential and run:

```powershell
# 1. log in (creates a fresh token in %USERPROFILE%\.npmrc), or paste a new granular token with
#    read+write access to packages:
#    //registry.npmjs.org/:_authToken=npm_...
npm login

# 2. verify the identity first — a 401 here means the token is still bad
pnpm whoami          # or: npm whoami

# 3. publish from this directory
cd packaging\npm
pnpm publish --no-git-checks --access public

# 4. verify what the registry actually serves
npm view trayiconguard version dist.tarball dist.integrity
```

After the package is live, add a row to the READMEs:

```text
npx trayiconguard install
```
